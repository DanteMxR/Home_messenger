# 💬 Веб-мессенджер

Современный веб-мессенджер, построенный на Next.js с поддержкой real-time общения для локальной сети.

## 🎯 Описание проекта

Это лёгкий веб-мессенджер, который можно запустить на локальном компьютере и использовать с друзьями через LAN/IP. Приложение работает на одном порту, имеет систему авторизации и современный пользовательский интерфейс.

## 🛠️ Технологический стек

### Основные технологии:
- **Next.js 15+** (App Router) — фронтенд + бэкенд (API Routes, SSR/CSR), единый порт
- **Prisma ORM** — работа с базой данных
- **SQLite** — лёгкая встроенная база данных (без дополнительной установки)
- **Socket.IO** — чат в реальном времени
- **JWT + cookies (httpOnly)** — безопасная авторизация
- **bcrypt** — хэширование паролей

### UI компоненты:
- **TailwindCSS** — базовые стили
- **shadcn/ui** — готовые красивые компоненты (формы, кнопки, модальные окна)
- **Lucide Icons** — иконки
- **Framer Motion** — анимации (готово к использованию)

## 📋 Предварительные требования

Перед установкой убедитесь, что у вас установлены:

- **Node.js** версии 18.0 или выше
- **npm** или **yarn** для управления пакетами
- **Git** для клонирования репозитория

## 🚀 Установка и запуск

### 1. Клонирование репозитория
```bash
git clone <repository-url>
cd messenger-app
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Настройка переменных окружения
Создайте файл `.env` в корневой директории:
```env
DATABASE_URL="file:./dev.db"
JWT_SECRET="your-super-secret-jwt-key-change-this-in-production"
NEXTAUTH_URL="http://localhost:3000"
NEXTAUTH_SECRET="your-nextauth-secret-key"
```

**⚠️ Важно:** Измените секретные ключи в продакшн-среде!

### 4. Инициализация базы данных
```bash
npx prisma migrate dev --name init
npx prisma generate
```

### 5. Запуск приложения

#### Режим разработки:
```bash
npm run dev
```

#### Продакшн сборка:
```bash
npm run build
npm run start
```

Приложение будет доступно по адресу: `http://localhost:3000`

## 🔧 API Документация

### Аутентификация

#### POST `/api/auth/register`
Регистрация нового пользователя
```json
{
  "username": "string",
  "email": "string", 
  "password": "string"
}
```

#### POST `/api/auth/login`
Вход в систему
```json
{
  "email": "string",
  "password": "string"
}
```

#### POST `/api/auth/logout`
Выход из системы

#### GET `/api/auth/me`
Получение информации о текущем пользователе

### Пользователи

#### GET `/api/users?search=query`
Получение списка пользователей с поиском

### Сообщения

#### GET `/api/messages?receiverId=id`
Получение сообщений с конкретным пользователем

#### POST `/api/upload`
Загрузка файлов
```form-data
file: (binary file data)
receiverId: string
content: string (optional)
```

### Файлы

#### GET `/api/uploads/[filename]`
Получение загруженного файла по имени

## 🗄️ Схема базы данных

### Таблица `users`
- `id` - уникальный идентификатор
- `username` - имя пользователя (уникальное)
- `email` - email (уникальный)
- `password` - хэшированный пароль
- `avatar` - аватар пользователя (опционально)
- `isOnline` - статус онлайн
- `lastSeen` - время последнего входа
- `createdAt` - дата создания
- `updatedAt` - дата обновления

### Таблица `messages`
- `id` - уникальный идентификатор
- `content` - содержимое сообщения
- `senderId` - отправитель
- `receiverId` - получатель (для личных сообщений)
- `chatId` - групповой чат (для групповых сообщений)
- `isRead` - прочитано ли сообщение
- `fileName` - имя файла (для файловых сообщений)
- `fileUrl` - URL файла (для файловых сообщений)
- `fileType` - тип файла (для файловых сообщений)
- `fileSize` - размер файла (для файловых сообщений)
- `createdAt` - дата создания
- `updatedAt` - дата обновления

### Таблица `files`
- `id` - уникальный идентификатор
- `name` - имя файла
- `url` - URL файла
- `type` - тип файла
- `size` - размер файла
- `messageId` - ссылка на сообщение
- `createdAt` - дата создания

### Таблица `chats` (готово для групповых чатов)
- `id` - уникальный идентификатор
- `name` - название чата
- `isGroup` - групповой ли чат
- `createdAt` - дата создания
- `updatedAt` - дата обновления

## 📤 Отправка файлов и изображений

Новая функция позволяет пользователям отправлять файлы и изображения в чате:

1. Нажмите на значок скрепки 📎 в поле ввода сообщения
2. Выберите файл из файловой системы
3. Файл будет автоматически загружен и отправлен получателю

### Поддерживаемые типы файлов:
- Изображения: PNG, JPG, JPEG, GIF
- Документы: PDF, TXT, DOC, DOCX
- Другие файлы: любые форматы

### Отображение файлов:
- Изображения отображаются в виде предварительного просмотра прямо в чате
- Для других файлов отображается значок с названием и возможностью скачивания

### Хранение файлов:
- Все загруженные файлы сохраняются в директории `uploads/`
- Каждый файл получает уникальное имя с временной меткой
- Информация о файле сохраняется в базе данных

### Вставка изображений из буфера обмена:
- Скопируйте изображение в буфер обмена (Ctrl+C)
- Вставьте его в поле ввода сообщения с помощью Ctrl+V
- Изображение будет автоматически загружено и отправлено

## 🔧 Устранение неполадок

### Проблема: Приложение не запускается
**Решение:**
1. Убедитесь, что установлены все зависимости: `npm install`
2. Проверьте файл `.env` на наличие всех необходимых переменных
3. Выполните миграции: `npx prisma migrate dev`

### Проблема: Socket.IO не подключается
**Решение:**
1. Убедитесь, что сервер запущен
2. Проверьте консоль браузера на ошибки
3. Убедитесь, что порт 3000 не занят другим приложением

### Проблема: Ошибки базы данных
**Решение:**
1. Удалите файл `dev.db` и выполните: `npx prisma migrate dev`
2. Проверьте права доступа к файлам
3. Убедитесь, что путь в `DATABASE_URL` корректен

### Проблема: Ошибки аутентификации
**Решение:**
1. Проверьте `JWT_SECRET` в файле `.env`
2. Очистите cookies браузера
3. Проверьте правильность данных для входа

## 🌐 Развертывание

### Локальная сеть (LAN)
1. Узнайте IP-адрес своего компьютера:
   ```bash
   # Windows
   ipconfig
   
   # Linux/Mac
   ifconfig
   ```

2. Обновите `NEXTAUTH_URL` в `.env`:
   ```env
   NEXTAUTH_URL="http://YOUR_IP_ADDRESS:3000"
   ```

3. Запустите приложение:
   ```bash
   npm run build
   npm run start
   ```
4. Другие устройства в сети смогут подключиться по адресу:
   `http://YOUR_IP_ADDRESS:3000`

### Продакшен развертывание
1. Настройте переменные окружения для продакшена
2. Используйте HTTPS в продакшене
3. Настройте обратный прокси (nginx/Apache)
4. Рассмотрите использование PM2 для управления процессом
